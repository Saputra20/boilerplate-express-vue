# User Journey Proposal

1. User opens Product Intelligence.
2. CMS requests authorized source list and latest freshness.
3. User selects approved source and bounded date range/category.
4. CMS requests trend series and displays daily historical points with metric definitions.
5. User inspects source, observed time, collection status, and unavailable fields.
6. Empty state explains no stored observations; stale state explains last successful collection; error state preserves prior visible data where safe.
7. User cannot edit snapshots, trigger arbitrary URLs, or infer unsupported marketplace claims.

Mobile: filters stack, chart/table can scroll without page overflow, labels and focus remain accessible.
