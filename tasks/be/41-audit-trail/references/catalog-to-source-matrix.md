## Reading rules

- Generic business and generic authentication events persist in `audit_events` through `apps/api/src/modules/audit/services/audit.service.ts`.
- Login, refresh, and logout security events persist in separate `auth_audit_events`. They are never merged into, read by, or exposed through Audit Trail.
- `recordInformational` means post-commit best-effort in the approved CMS paths: owner transaction commits first; append failure is swallowed and one sanitized Pino error is emitted by the audit service.
- `recordRequired` means append participates in owner transaction and failure aborts the owner operation. Existing authentication/password/email-verification semantics remain unchanged.
- Generic `audit_events.createdAt` is database-generated by `audit_events.created_at DEFAULT now()` in `apps/api/src/config/drizzle/schema/audit-events.schema.ts:6-35`. Emitters do not accept browser timestamps.
- In the approved CMS rows, action is the repository-owned constant `eventType`; target is repository-owned `resourceType` plus committed resource ID; request and session context comes from authenticated controller context.
- A service-layer `auditEvent`/`event` helper creates context passed to a repository. It is not the persistence boundary. The repository reconstructs the persisted event type, target, actor snapshot, and allowlisted metadata.
