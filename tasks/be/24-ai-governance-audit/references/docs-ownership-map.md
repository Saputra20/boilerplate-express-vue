# Documentation Ownership Map

| Document | Canonical responsibility |
| --- | --- |
| `AGENTS.md` | Authority, scope, approval, hard stops, task workflow |
| `docs/API.md` | Current API behavior and verified API/OpenAPI policy |
| `docs/ARCHITECTURE.md` | Durable module/layer/composition boundaries |
| `docs/DEVELOPMENT.md` | Local setup, test boundaries, operational developer workflow |
| `docs/SECURITY.md` | Durable security rules and secret handling |
| `docs/DATABASE.md` | Schema, migration, retention, and data-safety facts |
| `docs/OPERATIONS.md` | Verified runtime operations and failure/recovery behavior |
| `docs/CONVENTIONS.md` | Naming, file placement, imports, validation, test conventions |
| `docs/PRD.md` | Product problem, goals, users, workflows, requirements |
| `docs/PRODUCT.md` | Product navigation, roles, priorities, non-goals |
| `docs/DOMAIN.md` | Bounded contexts, vocabulary, entities, invariants |
| `docs/DESIGN.md` | Visual direction, responsive and accessibility requirements |
| `.codex/skills/**` | Reusable execution method, not current implementation truth |
| `tasks/**` | Task-specific scope, constraints, tests, and evidence |

Secondary copies should summarize or link to the canonical owner instead of creating competing rules.
